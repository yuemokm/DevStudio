## 2. Resize Handles

### Architecture

Implemented inside the existing `getOverlayScript` iframe injection script, alongside the existing select/hover/drag/keyboard-nudge logic.

### Handle Rendering

- On element select, create a `position: fixed` container div (`pointer-events: none`, `z-index: 10000`) appended to `<body>`.
- Place 8 resize handles inside the container (`pointer-events: auto`), each 8×8 px:
  - Four corners: `nw`, `ne`, `sw`, `se`
  - Four edges: `n`, `s`, `e`, `w`
- Handle styling: background `#e94560`, white 1 px border, `cursor` set to matching direction.
- Handle positions computed from `selectedEl.getBoundingClientRect()`.
- On window `scroll` or `resize`, recalculate and reposition handles.
- On `unselect`, remove the handle container.

### Resize Interaction

- `mousedown` on a handle:
  - Record start mouse position, element `offsetWidth`/`offsetHeight`, current `translate` values.
- `mousemove`:
  - Compute `dx`, `dy` from start position.
  - Adjust dimensions based on handle direction:
    - `e` → `width += dx`
    - `w` → `width -= dx`, `translateX += dx` (keep right edge fixed)
    - `s` → `height += dy`
    - `n` → `height -= dy`, `translateY += dy` (keep bottom edge fixed)
    - Combinations (`nw`, `ne`, `sw`, `se`) apply both axes.
  - Apply `style.width`, `style.height`, `style.transform` directly to `selectedEl`.
  - Enforce minimum 10 px for both width and height.
- `mouseup`:
  - Send `postMessage({ type: 'style-change', vid, payload: { property, value } })` for `width`, `height`, and `transform`.
  - React layer persists via `updateNodeAttr` on the `style` attribute (same path as drag-move).

### Coexistence with Drag Move

- During resize, `isDragging` flag is not used; a separate `isResizing` flag prevents drag and hover interference.
- After resize completes, `selectedEl` remains selected; handles are recreated at the new bounding rect.

## 3. Delete Element

### Interaction

Press `Delete` key while an element is selected.

### Flow

1. **Iframe overlay script** `keydown` listener:
   - If `e.key === 'Delete'` and `selectedEl` exists:
     - Clear outline and cursor from `selectedEl`.
     - Set `selectedEl = null`.
     - Send `postMessage({ type: 'delete-request', vid: dragVid })`.
2. **React layer** (`PreviewPanel` message handler):
   - On `delete-request`:
     - Call `store.removeNode(vid)` to remove the node from the AST. This also clears `selectedVid`, `selectedElement`, and sets `hasUnsavedChanges = true`.
     - Send `edit-bridge` `remove` message to the iframe so the overlay script removes the element from the live DOM.
3. Because `selectedVid` becomes `null`, the existing sync effect sends `unhighlight` to the iframe.

### External Delete Fallback

If the iframe loses focus (user clicks a side panel), the `Delete` key is captured by the React layer. It calls `removeNode(vid)` and sends the `remove` bridge message, producing the same result.
